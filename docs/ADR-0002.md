# ADR-0002：分支 fork 探针与提示词编排扩展面结论

- 状态：accepted（2026-08）
- 依据：PLAN_V2.md §P3E / §6.6；ADR-0001（版本锁定与扩展面约束）
- 补充：D-11 决策（§4a）于 2026-08 由用户确认选 c；P3F 已按此落地

> 探针基线：DSH `0.1.0-rc.6`（npm `next` dist-tag，与参考基线 `47f9438` 同源发布）。以下结论均来自对已安装包公开类型声明的阅读，引用「包名 + 公开符号」，不含源码文件路径。与 [PROGRESS.md](./PROGRESS.md) 的 Phase 0 P0-13/14/15 与 P3E/P3F 条目互见。

## 探针结论

### 1. P3E session fork 面 — VERIFIED

| 事实 | 公开符号 |
| --- | --- |
| fork 创建活的子会话，取源会话 inclusive 事件前缀为种子 | `@deepseek-ai/dsh-session` `SessionStore.fork(source, boundary?, childSessionId?)` |
| 拒绝码：`SESSION_NOT_FOUND` / `SESSION_NOT_LIVE` / `SESSION_ALREADY_EXISTS` / `INVALID_BOUNDARY` / `OPEN_TURN`（前缀不得止于未结束 turn 内） | `SessionForkError` |
| 持久谱系由会话头承载，无需 Gray 副本 | `SessionHeader.parentSession` / `seedLength`（另有 `agentPreset`、`cwd`） |
| 会话 + agent 同建（经 agent-loop 工厂） | `@deepseek-ai/dsh-agent` `AgentRegistry.create({ sessionId, seed, meta })`；meta 接受 `cwd` / `parentSession` / `seedLength` / `agentPreset` |
| 无工厂时抛 `'no agent factory registered (load an agent-loop plugin)'`；Gray 适配降级为 `ctx.sessions.create`（仅会话，`agentAttached = false`） | — |
| 消息投递面：`followup` = 新 turn + wake | `Agent.followup(message)` / `Agent.inject(message)` / `Agent.steer(message)` |

结论：P3E（树状分支）无需任何 DSH 内核改动即可实现；本仓库已按此落地（`packages/plugin/src/branches/`），采用「agents.create fork + Gray sidecar revision/CAS + 软删除」语义。

决策：侧边分支事件（`graycode/branch/*` 持久会话事件）本期不做 —— 见第 2 条 GAP。

### 2. 第三方自定义 SessionEvent 持久化 — GAP

- `SessionEventMap` 可经 module augmentation 扩展事件类型（dsh-agent、dsh-tools 自身即如此），`Session.append(type, data)` 也接受自定义类型。
- 但 `append` 不会写入事件信封的 `ignorable` 标记；而 dsh-session 公开契约规定：未识别类型且无 `ignorable: true` 的事件，持久化读取方必须拒绝重建整个会话（`SessionEvent.ignorable` 文档语义）。第三方插件事件对 DSH 官方持久化后端不可见，因此追加自定义事件会把会话档案置于「不可重建」风险。
- 结论：第三方插件「可持久化的自定义会话事件」在 rc.6 无公开注册面 → 标记 GAP。P3E 改用 sidecar JSON（`<dataRoot>/branches/groups.json`，原子 tmp+rename 写）作为分支元数据真源；分支事件的会话内落点推迟到 DSH 提供公开 ignorable 事件注册机制或官方确认插件事件通道后再做（Phase 4/6 重评）。
- 附带决策：后续 P3F 若需要给会话追加提示词相关事件，同样走 sidecar 或等到该 GAP 关闭。

### 3. P0-13 system-prompt section 组合 — VERIFIED

| 事实 | 公开符号 |
| --- | --- |
| section 注册：唯一名 + order + 静态文本或 provider 文本 + 可选 complete；上下文、变量、工具注册与最终组装 | `@deepseek-ai/dsh-system-prompt` `SystemPrompt`：`section()` / `context()` / `variable(name, provider)` / `tools()` / `suppressRuntimeContext()` / `assemble()` |
| 严格 `{{variable}}` 插值 | `renderPrompt()` |
| scoped（agent.ctx）注册 shadow 同名全局 section/context/variable；`system-prompt/assemble` waterfall 返回权威 assembly | scope 语义 |
| 部署 persona 槽位可被 agent preset 替换 | `PERSONA_SECTION = 'deployment:persona'` / `PERSONA_ORDER = 0` |

结论：Gray 静态模板 + `{{$MODULE}}` 占位符 + customPrefix/Suffix 可映射到 section（模板）+ variable（占位符模块）+ 按 agent scope 注册；P3F 的「静态模板/占位符/模式切换」面可行。占位符模块（WORKSPACE_FILES/OPEN_TABS/ACTIVE_EDITOR/DIAGNOSTICS 等）中编辑器专属模块在 DSH 无宿主语义，需降级或删除（与 §6.4 一致）。

### 4. P0-14 请求构造层注入临时消息 / thought part — GAP

- `agent/pre-step` waterfall 只能替换进入步骤的 `UserMessage[]`（user 角色）；`agent.inject` 只接受 user 角色消息。
- `agent/request` waterfall 只能替换 `LlmCallConfig`（provider/model/effort/sampling），文档明确「不能修改消息」。
- `llm/stream` waterfall 收到完整 `GenerateOptions`，但 loop 构建的请求带 `markAgentLoopRequest` 标记且深冻结，文档明确「只读，永不重写」。
- `ReasoningBlock { type: 'reasoning' }` 与 `createAssistantMessage` 存在，但没有任何公开入口把临时 assistant 消息 / thought part 注入请求而不写会话日志。

### 4a. D-11 决策（已定，2026-08）：选 c —— system-prompt context 注入

- 选项：a) 接受「写入会话日志」语义差异；b) 请求 DSH 官方扩展点；c) 以 system-prompt section/variable 注入等效文本。
- **决策 = c**（用户确认）。理由：完全公开 API、不污染会话日志、无需 `as any` 绕过；代价是失去 assistant 角色与 thought part 形态。
- 语义映射与已知降级点已落在 `packages/plugin/src/prompt/README.md`；实现见 `packages/plugin/src/prompt/`（domain/service/injector/tools，P3F 已落地，53 用例）。
- 后续升级 DSH 时重跑本探针：若官方开放请求构造注入点（如消息级 waterfall 或临时消息 API），优先改回公开机制，替换 `[thinking]` 文本前缀为 typed thought part。
- **2026 修订（P3F v2）**：A1 请求构造层（§4b）落地后，**c 路径已被取代**——user/assistant 条目以真实消息注入，`[thinking]` 文本前缀与系统段落路径已删除（主人决策：fakeThought 绝不降级为文本）。本节保留作历史决策记录。

### 4b. A1 请求构造层（2026-09 实现，2026 修订为默认启用）：llm/stream 改写 = 非契约用法

- **SPIKE 复核（.d.ts 实证）**：`isAgentLoopRequest(request)` / `markAgentLoopRequest` 为
  dsh-llm 公开导出（`lib/types/call-config.d.ts` L46/L52）；`llm/stream` waterfall 签名
  `(options, next) => AsyncIterable<StreamChunk>`（`lib/types/index.d.ts` L43）；
  `ReasoningBlock {type:'reasoning'}` 与 `createAssistantMessage` 存在
  （`lib/types/message.d.ts`）。实现见 `packages/plugin/src/thoughts/`。
- **非契约点**：llm/stream 文档明确 loop 请求深冻结、只读、永不重写。实现以**不可变改写**
  规避深冻结——构造新 options 对象 + 新 messages 数组，绝不 mutate 原对象；重写产物
  `markAgentLoopRequest` + `deepFreeze` **成对**处理（与宿主 buildRequest 同契约）；
  WeakSet 短路重入（每个请求恰改写一次）；任何异常 fail-closed 透传原请求。
- **默认启用（2026 修订，主人决策）**：`thoughts.enabled` / `prompt.requestLayer` /
  `sendHistoryThoughts` 等默认 true；组合根 **AND 联动**（thoughts 实际启用 =
  `thoughts.enabled && prompt.requestLayer`，requestLayer 翻转时主动重派生）。
- **fakeThought typed-only（主人决策，硬约束）**：fakeThought 只以 `{type:'reasoning'}`
  块注入真实 assistant 消息；**绝对禁止 `[thinking]` 文本前缀降级**——渠道无法承载时
  思维链不注入（gate 关）而非降级。D-11=c 的段落路径已删除（§4a 修订）。
- **entries 唯一组装（P3F v2）**：preset 条目（可排序）为唯一组装方式——system 条目
  合并进系统提示词，user/assistant 条目真实消息注入，chat_history 条目决定历史前后
  位置（before=列表最前、after=当前回合 user 消息之前，对齐原版
  findCurrentTurnStartIndex）；legacy 三段式（template + dynamicTemplate 分路）取消。
- **宿主提示词覆盖（overrideHostPrompt）**：agent 作用域 `system-prompt/assemble`
  瀑布过滤宿主 sections（保留 `graycode:persona` + `graycode:prompt`），被移除内容
  中和渲染后以 `{{graycode_dsh_prompt}}` 变量可引用；`{{$TOOLS}}` →
  `{{graycode_tools}}`（瀑布无条件提供）；contexts 按名过滤；弃用
  `suppressRuntimeContext()`（一刀切会清掉自己的 context）。complete section 为已知
  约束（当前安装集无 complete，升级 DSH 时重跑探针）。
- **动态上下文 preserve**：`systemPrompt.context` 注册 `graycode.todo` /
  `graycode.memory`，快照由宿主持久化进历史（按文本去重、变化追加、旧快照原位保留、
  compaction 可清理），前端宿主 ContextInjectionRow 自动展示。
- **接受差异**：deepseek-official 渠道 serialize 在普通回合丢弃 assistant reasoning 块
  → typed reasoning 在该渠道到不了 wire（pi-ai 渠道保留）；按主人决策**不降级文本**。
- **剩余动作**：真实 profile 挂载顺序探针 + 真实渠道验证待排期；DSH 官方开放消息级
  注入面后优先改回（ADR-0002 决策 3）。

### 5. P0-15 sendHistoryThoughts 渠道等价开关 — SPIKE

- 当前开发环境未安装 dsh-llm-pi-ai 等渠道适配包（dsh-llm 仅暴露 `reasoningEffort` / `ReasoningBlock` / `StreamChunk` reasoning-delta 等中性词汇），渠道侧「发送历史思考内容」开关是否存在、默认值如何（base.ts 注释默认 true 与 formatter `?? false` 的分歧）无法在本环境确认。
- 结论：标记 SPIKE，纳入 Phase 2 provider matrix（reasoning 内容维度）验证；P3F 的 fakeThought 发送侧过滤依赖该开关，属于 P0-14 GAP 之后的次阻断项。

## 决策

1. **P3E 按 VERIFIED 面实现**（`packages/plugin/src/branches/`）；`graycode/branch/*` 分支事件延后至 GAP 关闭。
2. **P3F 静态模板/占位符/模式**按 system-prompt section + variable 实现（已落地 `packages/plugin/src/prompt/`）；条目编排与 fakeThought 按 **D-11 = c**（system-prompt 文本注入，见 §4a）实现，不写会话日志、不伪造 thought part；sendHistoryThoughts 作为注入时门（默认 false，P0-15 SPIKE 结论见 provider matrix）。
3. **升级 DSH 时**（独立兼容 PR）重跑上述探针，GAP 项若官方关闭则优先改回公开机制，不长期持有 sidecar 特例与文本注入特例。

## 后果

- 探针状态回写 PROGRESS.md：P0-13 定论（VERIFIED），P0-14 / P0-15 定为 GAP / SPIKE（P0-15 已随 provider matrix 落地为注入时门默认 false）；P3E 由 pending 转「已按 VERIFIED 面实现」，P3F 已按 D-11 = c 落地（`src/prompt/`，53 用例）。
- 分支元数据以 sidecar 为真源，dsh Session 仅承载对话正文与原生谱系（`parentSession` / `seedLength`），不保存 Gray 副本。
- 分支事件与提示词相关会话事件在公开 ignorable 注册机制出现前一律不入会话日志，避免「不可重建」档案风险。
- P3F 的 fakeThought / 条目编排按 D-11 = c 以 system-prompt 文本注入实现（无 `as any` 或私有导入绕过，ADR-0001 决策 2 仍适用）；GAP 关闭前不引入 typed thought part。
