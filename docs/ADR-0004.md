# ADR-0004：稳定 workspaceId 注册表（立项）

- 状态：accepted（2026-08，立项；实施另立计划）
- 依据：PLAN_V2.md §5.4（领域分层）/ §7（迁移）；ADR-0001（版本锁定与扩展面约束）；
  本仓库 Phase 5 决策 D-1（scope 覆盖可视化）/ D-6（立项）
- 前置事实：
  - DSH 工作区记忆目录名 = `sha256(normalizeWorkspaceKey(cwd))` 前 16 hex
    （`packages/plugin/src/memory/service.ts` `scopeKeyToDirName`，私有）；
  - 旧 Gray 的 memory-workspaces 目录名同样为 `sha256(normalizeWorkspaceKey(fsPath))`
    前 16 hex（迁移侧 `workspaceScope.test.ts` 已验证两边一致）；
  - 因此工作区记忆的「身份」= 归一化 cwd 的哈希，**cwd 一旦变化（项目移动 / 盘符 /
    大小写 / 仓库改名 / 换机器）→ 哈希变化 → 记忆在新目录重建，旧记忆「漂移」失联**。

> 本 ADR 只记录决策与边界（D-6 立项）。实施细节（schema、迁移路径、并发与回滚）
> 由后续独立计划承接；本仓库当前已落地的 D-1 scopeOverrides（用户显式重定向）是
> 注册表的第一个手动脉冲，注册表是它的自动化后继。

## 问题

1. **记忆失联**：memory 域按 cwd 哈希寻址。用户重命名/移动项目目录后，工作区记忆
   留在旧哈希目录，新会话在旧 cwd 下也取不回（别名未解析）。
2. **checkpoint 孤岛**：checkpoint 备份按 `ws_<rootId>/` 组织，rootId 同样派生自路径
   指纹（`CheckpointWorkspace.ts`）；路径漂移后存档与当前工作区无法配对。
3. **迁移重映射无持久化**：D-1 的 scopeOverrides 是「每次 apply 显式传入」的一次性
   覆盖，不跨会话记忆；用户修正过一次的目标路径无法自动复用于后续迁移。
4. **多域路径解析重复**：memory（getWorkspace）、checkpoints（rootId）、stagedWrite
   （写路径一致性）各自独立解析 cwd→目录，别名/移动逻辑若分散实现必然不一致。

## 决策

**立项：持久化「稳定 workspaceId 注册表」，作为 cwd → 稳定工作区身份的唯一权威映射。**

- **注册表位置**：`<dataRoot>/workspaces/registry.json`（与 migration ledger / runs 同级，
  独立文件域；原子 tmp+rename 写，同 stagedWrite 惯例）。
- **记录形状（草案）**：

  ```json
  {
    "version": 1,
    "entries": {
      "<stableId>": {
        "cwd": "/abs/current/path",
        "aliases": ["/old/path/a", "/old/path/b"],
        "firstSeenAt": "…",
        "updatedAt": "…"
      }
    }
  }
  ```

- **stableId 生成**：首次登记时取 `sha256(normalizeWorkspaceKey(cwd))` 前 16 hex——
  与现有 `scopeKeyToDirName` **同算法**，因此既有工作区记忆目录/checkpoint rootId
  天然等于其 stableId，**注册表上线零目录迁移**。
- **别名解析语义**：任何域在「按 cwd 寻址」前先查注册表——cwd 命中某条记录的
  `aliases` 或旧 `cwd` → 解析为当前 `cwd`（返回权威路径）；未命中 → 按现行为。
  写侧同样先解析（避免旧路径写进新目录后两边都读不全）。
- **四域接入点（实施计划范围）**：

  | 域 | 接入点 | 收益 |
  | --- | --- | --- |
  | memory | `MemoryService.getWorkspace` 前先解析别名 | 路径漂移后仍取回原记忆 |
  | checkpoints | `ws_<rootId>` 解析与列表展示 | 存档 ↔ 工作区配对稳定 |
  | migration | `buildScopeMap` 建议目标改为注册表解析结果 | 自动修正漂移，覆盖表成为回退/显式覆盖 |
  | stagedWrite | 写路径一致性校验读注册表 | 防旧路径写入分叉 |

- **与 D-1 的关系**：scopeOverrides（用户显式 `global` / 绝对路径）优先级 **高于**
  注册表自动解析（显式指令 > 自动推断）；注册表负责「无人干预时的自动重定向」，
  两者不冲突。

## 边界与风险

- **一对多**：同一 cwd 可能对应多个 stableId 的场景（多根工作区、符号链接）需在
  实施时明确定义「权威条目」规则；注册表不合并不同 stableId 的记忆内容。
- **隐私**：注册表明文存储绝对路径（同 scope.json 现状）；属本地用户数据，
  不随任何报告/artifact 导出（仅内部寻址用）。
- **并发**：多进程写注册表需文件锁或原子合并（同 ledger 惯例）；本 ADR 不解决，
  实施计划引入。
- **降级**：注册表损坏/缺失 → 按现行为（cwd 直接哈希寻址）fail-open 于读取、
  fail-closed 于写入歧义（与 D-3 的「缺失即跳过」哲学一致：不猜测、不覆盖数据）。

## 决策

1. **注册表立项**（D-6 通过），实施另立计划；本期只落 D-1 scopeOverrides
   （手动脉冲）并保持接口向后兼容。
2. **stableId 与现有目录哈希同算法**，零迁移上线是硬约束（实施不得改变目录命名）。
3. **别名解析只读优先**：读路径解析别名，写路径解析别名 + 显式覆盖优先；
   不允许隐式「合并」两个 stableId 的记忆。
